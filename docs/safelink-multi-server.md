# SafeLink PC 多服务器

## 入口与行为

- 原生账号菜单增加“添加服务器”。
- 未登录的欢迎页、二维码、手机号、验证码和二次密码页面也提供“服务器与账号”入口。欢迎页位于右下角，登录步骤位于顶部；无需先登录默认服务器。
- 设置 → 服务器与账号：按服务器分组显示账号、原生头像及当前账号标记，每组可添加账号。
- 输入域名、IP 或 HTTPS 根地址，获取 `/.well-known/safelink-client.json`。IPv6 地址使用方括号。
- HTTPS 证书必须有效，IP 访问需要证书包含该 IP；不忽略证书错误，不跟随重定向。
- 校验 descriptor v1、RSA-2048/65537、PKCS#1 DER 的 SHA-256 身份和 MTProto 指纹。确认地址与公钥后才保存。
- 仅保存服务器不会切换账号。点击该服务器下“添加账号”才进入对应实例登录；未登录时可通过返回按钮或 Esc 回到原有账号。
- 登录过程中也能打开服务器列表，选择已有账号或另一服务器继续登录。列表复用原生账号头像、未读标记与右键菜单，未登录窗口不再依赖 SessionController。
- 同手机号、同用户 ID 在不同服务器属于不同账号。保留原有总账号数量限制，不改变 Premium 策略。

## 存储与隔离

- 公共服务器列表原子写入 `tdata/safelink-servers.json`，不保存验证码、密码或登录 Token，最多 32 台。
- 账号服务器绑定追加到原有加密 MTP 配置和授权数据末尾；缺失配置缓存时可从授权数据恢复绑定。
- 老账号默认绑定原 SafeLink 服务器，旧账号 ID 和排序兼容。
- 每个账号独立维护连接地址、公钥、授权密钥及会话 ID。新服务器不能覆盖既有账号绑定或替换全局默认服务器。
- 损坏绑定会清空可连接端点和公钥，不回退到默认服务器。已绑定账号禁用 Telegram 公共备用地址发现及调试端点覆盖。
- 拒绝已保存服务器的公钥或连接地址冲突，域名不是身份依据。此版本不自动迁移既有账号到更换了密钥的实例。
- 自定义服务器账号不要用旧版 PC 客户端打开同一份 `tdata`，旧版不认识服务器绑定字段。

## 验证

独立 Qt 测试仅依赖 Qt 6 Core/Network，不需要编译 Telegram：

```sh
cmake -S Telegram/SourceFiles/tests/safelink_server -B /tmp/safelink-server-tests -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/safelink-server-tests
ctest --test-dir /tmp/safelink-server-tests --output-on-failure
```

覆盖合法 descriptor、身份篡改、长度与字段边界、IPv4/IPv6、危险 URL、旧账号兼容和跨实例同 ID 隔离。

发布前仍需在完整 PC 构建环境验收：

1. 旧 `tdata` 升级后原账号仍连接原服务器。
2. 添加第二实例，确认公钥后分别用相同手机号和用户 ID 登录，两边账号同时存在。
3. 切换账号后消息、头像、未读和文件下载来自对应实例。
4. 完整退出再启动，两边账号及服务器分组不丢失。
5. 添加服务器后取消获取配置、取消信任、取消手机号/验证码/二次密码登录，均可返回原账号；已保存的服务器保留。
6. 错误证书、超时、HTTP 重定向、超长响应、错误指纹、同地址换公钥均被拒绝。
7. 备份测试账号数据后，移走该账号的配置缓存，确认从加密授权数据恢复其服务器；损坏绑定时确认不会访问默认服务器。
8. 账号数达到限制时显示原生账号上限提示，不误复用其他实例的未登录账号。
9. 全新 `tdata` 下，从欢迎页、二维码页或手机号页打开服务器列表，添加并确认第二实例公钥后登录；检查“当前服务器”和实际连接地址一致。
10. 在验证码、邮箱和二次密码步骤打开服务器列表，取消选择保留原登录流程；切换到其他服务器后不会将验证码提交到旧实例。已有账号可从列表直接返回。
11. 检查最小窗口、不同界面缩放、语言、深色模式以及可用更新按钮同时出现时，入口没有遮挡且可点击。

当前工作机缺少 Qt、PC 子模块依赖和配置后的构建目录；未执行 C++ 编译、上述 Qt 测试或双实例客户端运行验收。
